# 일본주식 모의투자

진짜 도쿄 증권거래소 시세(야후 파이낸스, 열쇠 없이 씀)로 가짜 100만엔을 굴려 보는 앱. 지갑과 주문 기록은 내 Supabase 프로젝트(`fjtpocuslteewpyfonrs`)에 저장한다.

- 인터넷 공개: 안 함. 2026-09-24에 올렸다가 사용자 요청으로 거뒀다 (Vercel 프로젝트 삭제). 다시 올릴지는 나중에 결정
- 시작 현금 100만엔 · 수수료 없음 · 9종목(도요타·소니·닌텐도·키엔스·소프트뱅크·유니클로·혼다·미쓰비시UFJ·NTT)
- 1주 단위로 사고판다 (실제 일본 주식은 100주 단위가 많지만 연습용으로 줄임)
- 시세는 약 15~20분 늦다. 장이 닫혀 있어도 마지막 가격(종가)으로 거래할 수 있다
- 지갑이 하나뿐이라 주소를 아는 사람은 모두 같은 지갑을 쓴다
- 지금 상태: 화면·서버 완성, 저장창고는 **Supabase에 연결됨 — 단 `supabase-setup.sql`을 SQL Editor에서 한 번 실행해야 켜진다** (내 컴퓨터에서만 동작). 첫 화면(홈)은 현재가 → 내 지갑 → 사기/팔기 → 주문내역 순서로 한 화면에 보인다

## 켜는 법

1. `.env`에 `SUPABASE_URL`과 `SUPABASE_PUBLISHABLE_KEY` 넣기 (`.env.example` 참고, git에 안 올라감)
2. **처음 한 번만**: Supabase 화면 → SQL Editor → 새 쿼리에 `supabase-setup.sql` 내용을 붙여 넣고 Run (표 2개와 함수 4개가 만들어진다. 여러 번 실행해도 안전)
3. `npm install` → `npm start` (다른 앱과 겹치면 `PORT=3020 node server.js`)
4. 인터넷 창에서 http://localhost:3000

## API

| 방법 | 주소 | 하는 일 |
|---|---|---|
| GET | `/api/markets` | 종목 전체 현재 시세 + 장이 열려 있는지(`open`·`lunch`·`closed`) |
| GET | `/api/price?code=7203` | 종목 하나의 현재가 |
| GET | `/api/chart?code=7203&kind=today` | 짧은 그래프 자료 (`kind`: `today`·`months3`·`year1`·`year5`) |
| GET | `/api/history?code=7203&interval=day` | **상장 후 전체 기간** 일봉·주봉·월봉 (`interval`: `day`·`week`·`month`). 봉마다 `{t, open, high, low, close, volume}` — 선그래프는 `close`, 막대그래프는 `volume` |
| GET | `/api/wallet` | 현금·평가금액·수익률·보유 주식 |
| GET | `/api/orders?limit=50` | 주문 내역 (새 것부터) |
| POST | `/api/order` | 사기·팔기 `{ code, side: "buy"/"sell", qty }` |
| POST | `/api/wallet/reset` | 처음(100만엔)으로 되돌리기 |
| GET | `/api/health` | DB 연결 확인 |

- 응답 모양: `{ success, data }` / 실패하면 `{ success: false, message }`
- 주 수는 1 이상의 정수. 돈·주식이 모자라면 400으로 거절한다.

## 저장창고 (Supabase)

서버는 표를 직접 열지 않고, `supabase-setup.sql`로 만든 함수 4개만 인터넷 주소(`/rest/v1/rpc/…`)로 부른다.

| 함수 | 하는 일 |
|---|---|
| `jpinvest_get_wallet` | 지갑 조회 (없으면 100만엔으로 생성) |
| `jpinvest_list_orders` | 주문 내역 (새 것부터, 최대 200건) |
| `jpinvest_trade` | 사기·팔기 — 지갑 줄을 잠그고 돈/주식 확인 → 지갑·주문 기록을 한 번에 저장 |
| `jpinvest_reset` | 처음(100만엔)으로 되돌리기 |

| 표 | 내용 |
|---|---|
| `jpinvest_wallet` | 지갑 한 줄 (현금 + 보유 주식 `{코드: {수량, 평균매입가}}`) |
| `jpinvest_orders` | 주문 기록 (시간 · 종목 · 사기/팔기 · 주 수 · 체결가 · 금액 · 팔 때 번 돈) |

- 이 프로젝트에는 다른 앱의 `wallet`, `orders` 표가 이미 있다 → 건드리지 않고 이 앱은 `jpinvest_` 이름만 쓴다.
- 표는 잠겨 있다(RLS, 정책 없음). 공개용 열쇠로는 위 함수 4개만 부를 수 있고 표를 직접 읽거나 쓰면 거절된다.
- 공개용(publishable) 열쇠는 **서버(.env)에서만** 쓰고 화면(index.html)에는 넣지 않는다. 열쇠가 새면 남이 함수를 부를 수 있다 (연습용이라 감수).

## 시행착오

- **DB 연결 방식 바꿈 (2026-09-24)**: 처음엔 수업용 공용 DB에 비밀번호 주소(`DATABASE_URL`)로 직접 연결했다. 새 프로젝트는 공개용 열쇠 + 인터넷 주소(REST)만 받아서 `pg` 부품을 빼고 함수 호출 방식으로 바꿨다. 공개용 열쇠로는 표를 **만들 수 없어서** SQL Editor에서 한 번 실행하는 단계가 생겼다.
- 함수 SQL은 연습용 DB에서 트랜잭션 안에 돌려 22개 항목(사기·팔기·평균가·번 돈·모자람 거절·표 직접 접근 거절)을 시험하고 전부 취소(ROLLBACK)했다.
- 표·함수가 없을 때 서버가 "supabase-setup.sql 을 한 번 실행해 주세요"라고 알려 준다 (Supabase 오류 코드 `PGRST202`).
- Supabase 주소는 `…/rest/v1/`로 끝나도 서버가 알아서 다듬는다.


- **전체 기간 봉 (2026-09-24 시험)**: 열쇠 없는 무료 API는 야후 파이낸스뿐이다. Stooq(CSV)는 서버에서 부르면 403 접근 거부라 못 쓴다.
- 야후에 `range=max`로 물으면 일봉·주봉도 월봉(320개쯤)으로 뭉뚱그려 준다 → `period1=0&period2=지금`으로 기간을 직접 정해야 일봉 6,300~6,700개·주봉 1,300~1,400개·월봉 300여 개가 온다.
- 자료는 **야후가 가진 가장 옛날부터**다 (실제 상장일이 아님): 도요타 1999-05, 소니 2000-01, 닌텐도·키엔스 2001-01. 주식 분할은 이미 반영돼 있다.
- 휴장일에 야후가 채워 넣는 빈 봉(거래량 0, 시고저종 같음)이 일봉에 130개쯤 섞여 있어 서버에서 뺀다.
- 전체 일봉은 약 550KB. 서버가 일봉 1시간·주봉 6시간·월봉 12시간 기억해서 두 번째부터는 10ms대로 온다.

- 야후는 한 번에 한 종목만 준다 → 8종목을 동시에 묻고 15초간 기억(캐시). 야후가 실패하면 30분 안에 받은 값을 대신 쓴다.
- "오늘 5분봉" 요청 하나로 현재가·어제 종가·고저·거래량·작은 그래프를 다 얻는다.
- 장 열림 판단: 도쿄 시각 + 야후의 거래시간. 점심(11:30~12:30)은 따로 표시. 휴장일은 "문 연 지 30분 넘도록 오늘 시세 없음"으로 알아낸다.
- 야후는 해외 서버(Vercel)에서도 잘 된다 (2026-09-24 확인). 나중에 막히면 화면에 "서버에 연결하지 못했어요"가 뜬다.
- `vercel link`가 `.gitignore`에 `.env*`를 뒤에 또 붙여 `.env.example`이 제외됐다 → 줄을 정리해서 고쳤다.
- 화면(React를 인터넷에서 받아 바로 변환)은 처음 열 때 2~3초 걸린다. 그동안 빙글빙글 표시가 나온다.
